# ADR-0002 Languages and runtime

- Status: Accepted
- Date: 2026-10-11
- Deciders: owner (Python for simulation/analysis/pilots), orchestrator (API, viewer)
- Related: PH-005, PH-007, PH-013

## Context
- MVP goal: validate algorithms, API and financial viability. No end-user app.
- Owner chose Python for simulation, analysis and pilot tests.
- Python has the strongest optimization/simulation ecosystem (OR-Tools, PyVRP,
  NumPy, pandas, SimPy).
- Vercel supports FastAPI: it detects a FastAPI `app` and deploys it as one
  Vercel Function. Python functions default to 300 s max duration with Fluid
  compute; Hobby caps at 300 s, Pro/Enterprise up to 800 s.

## Options for the API
1. **Python + FastAPI** — same language and code as the solver; typed contracts
   via Pydantic; auto-generated OpenAPI docs; supported on Vercel.
2. TypeScript (Next.js/Hono) — second language, solver would be a separate service.
3. Go — fast, but no optimization ecosystem; second language.

## Decision
- **Python 3.12 everywhere.** FastAPI for the API (deployed on Vercel), Pydantic
  models shared between API, solver and simulator.
- Tooling: `uv` (deps), `ruff` (lint/format), `pytest`, `mypy` optional.
- **Viewer:** static HTML reports generated by each simulation run (Plotly charts,
  Leaflet maps via Folium), plus an index page. Viewable locally or published as
  static files on Vercel. Not part of the future product.
- Heavy runs (full-day simulations, parameter sweeps) run locally or in GitHub
  Actions, not in Vercel functions. API solves are bounded to fit the function limit.

## Consequences
- One language, one test stack. If solver runtime exceeds Vercel limits, revisit
  with an async job design (new ADR).
